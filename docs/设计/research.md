# Research: 规格驱动与资产复用阶段包

本文件把计划里的未知项收成已拍板的决定。地址、确认人、组件名仍然空白，空白本身就是决定，不是未完成的澄清。

## 1. 阶段包放在现有 `ai-agent/` 目录

- **Decision**: 可下载阶段包就是使用方工程里的 `ai-agent/` 规则、阶段说明和技能。公司现有安装入口只负责把这些文件放到工程中。规则正文以这些文件为准。
- **Rationale**: 开发组已经按这个目录工作。另挂一套只读目录会和现有阶段门禁分裂。章程已否定把过程材料挂到另一套只读目录。
- **Alternatives considered**: 统一 IDE 插件承载规则正文；做成另一套安装插件；把公共规则打成使用方必须整目录替换的包。前两种会让插件成为规则来源。整目录替换会清掉已填写的应用侧规则。

## 2. 更新时保留已填写的应用侧规则

- **Decision**: 首次放入阶段包时，写入六份应用规约的说明和空白事实栏。之后再次放入时，这六份文件若已存在则跳过，不覆盖。公共规则、阶段模板和技能属于发布版本，更新时写回发布内容。
- **Rationale**: 规格要求再次取得阶段包后，已填写内容仍在。公共规则被改过的副本不再是发布版本，所以更新可以写回公共规则。
- **Alternatives considered**: 把应用侧规则另存到阶段包以外的本地目录。开发组已经在 `ai-agent/agents/**/rules/` 里填写，再搬一次会制造第二份事实。

## 3. 不进入使用方流水线

- **Decision**: 阶段包不附带合并或构建流水线的核对步骤，也不附带校验和门禁。
- **Rationale**: 提供方不能干涉使用方流水线。章程禁止把核对步骤当作交付条件。
- **Alternatives considered**: 在使用方流水线中核对阶段包是否被改过。该方案无法落地，已放弃。

## 4. 查阅与决策分开，不新增技能

- **Decision**: 共用的资产规则写入 `ai-agent/rules/工程规约.md`。查找时机和决策写入现有阶段技能。远程查阅只有一个服务，名称 `glue`。契约写在 `ai-agent/mcp/glue.md`，内容以 `contracts/glue-lookup.md` 为准。服务进程、目录索引、程序包、文档、样例和令牌留在提供方，不打进阶段包。
- **Rationale**: 单独的查找技能可以被“帮我找个组件”直接调用，从而绕过阶段门禁。业务代码调用查阅服务也无法留下阶段审计。
- **Alternatives considered**: 新增目录技能；把查阅写进业务代码；由阶段技能在本地保存一份完整目录来代替远程查阅。本地完整目录会把文档和样例带进阶段包，并无法按版本拒绝过期内容。

## 5. 使用方如何接到查阅服务

- **Decision**: 使用方在自己的 IDE 配置里增加名为 `glue` 的查阅服务。地址保持空白，直到人提供。令牌从环境变量 `GLUE_TOKEN` 读取，不写入仓库。阶段包不替换使用方已有的整份 IDE 配置。
- **Rationale**: 地址目前没有事实。整文件替换会清掉使用方已经配置的其他服务。
- **Alternatives considered**: 在阶段包里放一份带示例地址的配置。示例地址会被当成可调用的依赖。

## 6. 尚未提供的事实保持空白

- **Decision**: 目录地址、文档宿主、样例库、第一个资产、查阅地址、确认人、服务名、仓库名、账号和命令，在规约、契约和计划中保持空白。实现不得填入 `panda-test`、`https://123.12.1.21`、`com.example.internal` 或任何自拟值。
- **Rationale**: 这些值在仓库和对话里都不存在。空表表示未知，对应阶段必须问人。
- **Alternatives considered**: 用占位地址让契约看起来完整。占位地址会在后续实现里被当成真地址。

## 7. 规格保鲜沿用打回

- **Decision**: 规格保持事实来源。已命名写入位置已有改动时，继续编码前由人确认漂移类别，再回到负责该类别的阶段。交付前的符合性评审再做一次。不根据代码差异回写规格，不另建同步轨迹。
- **Rationale**: 用代码差异改规格会让实现反过来定义需求。
- **Alternatives considered**: 另建一条轨迹，由人确认后把代码差异写回规格。该做法已在章程中否定。

## 8. 格式示例不放进可填写模板

- **Decision**: 六份应用规约只增加“填什么、只填已有事实、留空时哪一阶段问人、哪一阶段读取”。不另建示例文件。现有模板里的说明文字已经把空白事实和禁止编造写开。
- **Rationale**: 目前没有必须靠示例才能看懂的字段。既有材料里的示例坐标不是事实。
- **Alternatives considered**: 增加 `格式示例-不得照抄.md`。在没有真实格式需要演示时，这份文件只会重新引入假地址。

## 9. 检索只打登记索引，拉取只取点名对象

- **Decision**: 提供方把资产身份、版本清单和章节标题做成内存索引。概要设计只检索这层索引。详细设计按概要留下的标识做主键点查，再由人指定版本和章节，服务只读取那一章。样例先给清单，再按路径逐个读取。文档正文不进入倒排索引。命中超过 20 条时只返回命中数和标签分布。单章超过 256 KiB、单次样例正文超过 1 MiB 时拒绝。
- **Rationale**: 慢来自扫描手册和一次返回大量正文。身份索引与文档体积分开后，组件数量和文档页数不再决定检索时间。20 条是一次决策能看完的上限，用来阻止代理在长列表里自行挑选。
- **Alternatives considered**: 对全部文档做全文或向量检索；详细设计再做一次全库分类；服务在未指定版本时自动返回最新版。前两种会把文档体积带进每次查阅。自动选最新版违反“不得自动跟随更新版本”。

## 10. 发布范围

- **Decision**: 阶段包包含 `ai-agent` 下的工程规约、公共规约、阶段模板、技能、`mcp/glue.md`，以及首次安装的六份应用规约。不包含 `ai-agent/skills/coding/code-quality-skill/archive/`、本仓库的 `specs/`、`.specify/`、`.archify/`、`agent-skills/`、`docs/` 下的交接和设计说明，以及 `docs/工程规范_A.md`、`docs/工程规范_B.md`。
- **Rationale**: 归档的评审清单、编写这次设计的 Spec Kit 目录、以及两份示例工程规范都不是开发组的阶段规则。规格明确阶段包不含组件程序包、文档正文和样例。
- **Alternatives considered**: 把整个仓库打成一个包。使用方会收到编写过程、示例坐标和组件手册的位置，超出规格范围。
