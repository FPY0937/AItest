# Data Model: 规格驱动与资产复用阶段包

字段来自规格中的实体。没有事实的值保持空白，不设默认地址或默认人名。

## 可复用资产

提供方目录中的一条登记。阶段包不保存这份目录。

| 字段 | 含义 | 规则 |
|---|---|---|
| 标识 | 资产的稳定名称 | 必须来自查阅结果 |
| 一句话能力 | 它能做什么 | 概要设计可见 |
| 标签 | 分类用的词 | 概要设计可见 |
| 发布标识 | 用来引用一次发布的坐标 | 详细设计和程序设计可见；概要设计不可见 |
| 文档位置模板 | 该版本文档在哪里 | 不含正文 |
| 样例标记 | 与版本对齐的样例记号 | 样例自身测试通过后，该版本才可复制 |
| 维护人 | 谁维护这条登记 | 详细设计和程序设计可见 |
| 状态 | 在用、试验、停用 | 只允许 `active`、`experimental`、`deprecated` |

身份和版本分开存放。身份字段是标识、一句话能力、标签、维护人、状态。版本字段是版本号、发布标识、样例标记、样例测试是否通过。每个版本另有一份文档索引，每章一条，字段是章节标识、标题、顺序、字节数、内容校验和、对象键。文档正文和样例文件不在这些记录里。文件布局、字段和检索步骤见 [contracts/catalog-index.md](./contracts/catalog-index.md)。

校验：

- `deprecated` 不算命中，除非本次需求写明保留该旧资产。
- 不得从较新版本自动生成一条新的命中。

## 候选绑定

概要设计在恰好一个命中时留下的记录。

| 字段 | 含义 | 规则 |
|---|---|---|
| 资产标识 | 命中的那一条 | 只记录标识 |
| 标记 | 固定为「待详细设计绑定」 | 不是完成方式，不含版本 |

状态：

1. 概要记录候选。
2. 详细设计只消费这个标识。
3. 若详细设计看到的登记与概要矛盾，记录作废，回到概要设计。

零个命中时不产生候选绑定。多个命中时不产生候选绑定，工作停在待确认，一次只问一个问题。

## 完成方式

详细设计的决定。

| 取值 | 证据 | 允许条件 |
|---|---|---|
| 既有资产 | 文档名称和章节；资产名来自该页 | 概要已有候选，且读到的页面与候选一致 |
| 本服务实现 | 无 | 对应能力的查阅确实为零命中 |

未查阅不得写成「无」。多种不同能力可以各有一条完成方式。不得同时深入阅读多个候选后再挑选。

## 版本锁定

程序设计对一次使用写下的记录。

| 字段 | 含义 |
|---|---|
| 资产标识 | 与完成方式中的既有资产一致 |
| 版本 | 人在编码前确认的那一版 |
| 文档位置 | 该版本的文档位置 |
| 样例标记 | 与该版本一致 |
| 差异 | 相对样例，本服务还要写的部分 |

状态：写下后等待人确认。人确认前不得编码。确认后不得自动换成更新的版本。公共用法变化则锁定作废并停止。仅内部变化且公共用法不变时，另开子项，目标改为资产所在工程。

## 子项

| 字段 | 规则 |
|---|---|
| 编号 | 以 5 开头 |
| 概要模块 | 恰好一个 |
| 服务 | 恰好一个 |
| 目标工程 | 恰好一个 |

一次目录命中写在该子项的程序设计里，不回写应用规约的「必须复用」。

## 确认

| 种类 | 谁可以填写 | 作用 |
|---|---|---|
| 需求确认 | 需求应用规约中点名的人 | 只打开下一设计阶段 |
| 架构师确认 | 概要设计应用规约中点名的人 | 只打开下一设计阶段 |
| 漂移类别确认 | 人 | 只决定打回哪一阶段 |

代理不得填写前两种。姓名未提供时保持空白，并在该阶段询问。

作废：

- 范围、验收、优先级或受影响服务变化：前两种确认都作废，已有测试通过作废。
- 字段、状态、错误码或步骤顺序变化：程序设计作废，编码停止。这一条不是一次新的需求确认。

## 漂移类别

比较范围只包括已命名的写入位置和依赖声明。

| 类别 | 人确认后的去向 |
|---|---|
| 仅代码偏离 | 改代码，规格不变 |
| 方法、目标工程或资产版本变化 | 程序设计作废，编码停止 |
| 字段、状态、错误码或顺序变化 | 先回详细设计，程序设计作废 |
| 范围、验收、优先级或服务变化 | 两处确认重置 |
| 公共用法被破坏 | 按结构变更回到概要设计 |
| 无法判断 | 停止，只问一个问题 |

未分类时，继续编码的次数必须为 0。交付前的符合性评审使用同一张表再分类一次。

## 查阅审计

提供方对一次查阅留下的记录。阶段包不保存审计日志。

| 字段 | 含义 |
|---|---|
| 时间 | 查阅发生的时间 |
| 身份 | 谁发起查阅 |
| 查阅动作 | 四类动作之一，见查阅契约 |
| 资产标识 | 涉及的资产；分类查阅可为空直到命中 |
| 版本 | 涉及的版本；概要分类时为空 |
| 允许或拒绝 | 这次查阅是否被接受 |
| 原因 | 拒绝或停住的原因 |

## 应用侧规则

六份文件。事实栏在没有事实时为空。每个待填字段必须另有四项说明：填什么、只填已经存在的事实、留空时哪一阶段问人、哪一阶段读取。

| 文件 | 已有事实栏 | 读取阶段 |
|---|---|---|
| `ai-agent/agents/01_需求智能体/rules/需求应用规约.md` | 领域术语、存量系统约束、角色与权限、编号与来源、需求确认人、合规与数据 | 需求 |
| `ai-agent/agents/02_设计智能体/01_概要设计/rules/概要设计应用规约.md` | 架构师确认人；服务名仍以 `docs/应用架构.md` 已有内容为准 | 概要设计 |
| `ai-agent/agents/02_设计智能体/02_详细设计/rules/详细设计应用规约.md` | 子条目取号、对象与码表 | 详细设计 |
| `ai-agent/agents/02_设计智能体/03_程序设计/rules/程序设计应用规约.md` | 目标库与工作目录、必须复用、日志事务异常 | 程序设计 |
| `ai-agent/agents/03_编码智能体/rules/编码应用规约.md` | 仓库映射、语言与分层、日志与异常、数据访问、单元测试、验证命令 | 编码；表为空时改读程序设计 |
| `ai-agent/agents/04_测试智能体/rules/测试应用规约.md` | 环境、账号与权限、造数与清理、自动化、缺陷 | 测试设计与测试执行 |

「必须复用」只在人单独做治理修改时增加条目。一次资产选用不得增加条目。

文件状态：

1. 不存在：首次放入阶段包时写入带说明的空白模板。
2. 已存在：之后的阶段包更新跳过该文件。

## 变更类型

按顺序判断，命中即停：技术变更、结构变更、范围内改动。

- 多个代码库本身不是结构变更。
- 进程内资产不是新服务，也不是系统间调用。
- 技术变更不按能力重新匹配资产。
