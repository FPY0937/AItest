# 编码评估

## 评估对象

- `ai-agent/spec/{需求项编号}/{子条目编号}/{子条目编号}_编码记录_{短标题}.md`
- 记录中点名的 `git-repo-*` 或 `work/{需求项编号}/{目标库}/` 里的本次代码和测试

## 否决项（有一条即不通过）

- [ ] 程序设计未通过、不存在，或已标明作废、编码须停止，仍改了代码
- [ ] 改动超出程序设计列出的目标库与写入目录
- [ ] 业务代码写入了 `ai-agent/`、`docs/`，或写入了没有点名的代码库
- [ ] 擅自修改公共方法签名、字段或异常码
- [ ] 技术变更新增了程序设计写成「不适用」的业务类或方法
- [ ] 关键失败路径被吞掉，或异常码与详细设计对不上
- [ ] 存在无关重构，或升级了程序设计没有要求的依赖
- [ ] 本次新增或修改了有行为的类，却没有对应测试类；或该类本次改动的对外方法缺少成功或失败的测试方法。技术变更没有新业务类时，改为：新建了业务测试类
- [ ] P0 没有先失败后通过的记录。技术变更改为：没有既有套件或构建的实际结果，且验证表要求的失败测试也没有
- [ ] 用一个已经会通过的测试代替先失败的证明
- [ ] 验证命令来自别的仓，或只写了「应该可以通过」
- [ ] 未做设计符合审查或代码质量审查，任一边 Critical 未清零，或 P0 仍被阻塞却把总结论写成可交付
- [ ] 测试执行尚未完成，就把改动提交到了远程
- [ ] 有待锁定资产，人尚未确认锁定，仍改了代码
- [ ] 重写了程序设计已点名的资产，或复制了样例测试未通过、样例标记不等于锁定版本的文件
- [ ] 用 `GLUE_TOKEN` 取了程序包，或依赖声明不是人确认的显式版本
- [ ] 准备把编码评估写成通过，或在已有改动上继续编码，漂移尚未由人分类

| 改动收敛 | 15 | 只在点名的写入目录，无无关重构 |
| 仓内同构 | 15 | 分层和命名沿用该仓或工程规范 |

| 可审查 | 15 | 编码记录里设计符合和代码质量都有结论，且都无 Critical |
