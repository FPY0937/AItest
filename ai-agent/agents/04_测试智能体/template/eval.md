# 测试评估

## 评估对象

- `ai-agent/spec/{需求项编号}/{需求项编号}_测试设计_{短标题}.md`
- `ai-agent/spec/{需求项编号}/{需求项编号}_测试用例_{短标题}.md`
- 判断测试是否完成时，必看测试用例里的执行记录

## 否决项（有一条即不通过）

- [ ] 需求确认不是通过仍写出测试设计
- [ ] 没有测试设计，只有用例堆砌
- [ ] 需求里的验收没有全部追溯到测试用例，或某条 P0 验收没有用例 ID
- [ ] 把用例中的 P1 改成了 P0
- [ ] 业务需求缺主成功，或缺异常、权限路径。技术变更改为：没有行为保持或没有回退
- [ ] 步骤不可执行（无角色、无入口、无关键数据、期望含糊）。技术变更改为：看不出如何判定行为仍在、如何回退
- [ ] 用「正常流程 / 检查是否正确」代替期望结果
- [ ] 把类名、方法名或单元测试类写成了业务验收
- [ ] 编造了应用规约和需求里都没有的环境、账号
- [ ] 把一次性脚本或数据写进了 `docs/`
- [ ] 把编码记录里的单元测试通过写成了验收通过
- [ ] 声称测试完成，但 P0 没有执行结果，或结果为失败、阻塞
- [ ] 范围、验收或优先级已变，仍沿用旧的执行通过记录
- [ ] 调用了 glue，或把组件自身测试结果写成了 P0 通过

## 评分（通过线 80）

设计阶段用下表。执行未完成时，结论写「设计通过，测试未完成」。

| 项 | 分 | 标准 |
|---|---|---|
| 追溯完整 | 25 | 验收项都有用例 ID，P0 与需求一致。技术变更的行为保持和回退都有用例 |
| 设计有效 | 20 | 有等价类、边界、路径；没有规则时写明不适用。技术变更改为：回退步骤能执行 |
| 可执行 | 20 | 步骤与期望可交给他人直接跑 |
| 风险覆盖 | 20 | 业务需求覆盖权限、边界、失败、重复提交（适用时）。技术变更覆盖行为变化被漏测 |
| 复用克制 | 15 | 能引场景说明书则引用，不把单元测试算进验收 |

## 结论

- 设计结果：通过 / 不通过
- 执行结果：未开始 / 阻塞 / 完成
- 总分：
- 必须修改：
- 打回给：需求智能体 / 编码智能体 / 无需打回
- 可以分提：是 / 否
