# 详细设计评估

## 评估对象

`ai-agent/spec/{需求项编号}/{子条目编号}/{子条目编号}_详细设计_{短标题}.md`

## 否决项（有一条即不通过）

- [ ] 概要设计未通过，或架构师确认不是通过
- [ ] 子条目编号不是 `5` 开头，或范围与概要模块、服务对不上
- [ ] 一个子条目写入了两个服务的契约
- [ ] 技术变更写了业务字段、状态、处理步骤或异常码
- [ ] 业务需求缺少成功和失败都要读的字段，或失败时调用方看见什么没有写。无状态、无新字段时未写「不适用」或「沿用既有字段」也算缺失
- [ ] 重复提交会多写事实，却没有幂等键和再次提交的结果
- [ ] 数据归属与概要设计不一致，或新增了概要里没有的服务、调用
- [ ] P0 的 UC 写在「不包含」里，又没有另一个子条目编号承接
- [ ] 步骤有分支却没有与步骤一致的流程图；或多个调用的中间失败能被看见，却没有时序图。另附了图片，或画了类图、方法清单
- [ ] 出现具体语言代码，或 `work/`、`git-repo-*` 路径
- [ ] 阻塞程序设计的待确认仍在，仍交给程序设计
- [ ] 未查阅却把证据写成「无」，或在详细设计里改选了概要没有记下的资产
- [ ] 完成方式是既有资产，却没有读到的文档名称和章节
- [ ] 人未指定章节就读取了正文，或一次拉下了多个候选的正文

## 评分（通过线 80）

| 项 | 分 | 标准 |
|---|---|---|
| 范围对齐 | 20 | 子条目能指回概要模块、服务和 UC。技术变更改为：能指到目标代码库 |
| 状态闭合 | 20 | 有迁移时进入和离开成对。无状态或技术变更写明「不适用」即得分 |
| 契约可实现 | 25 | 字段、校验、重复提交的结果能直接写成方法。技术变更写明证明和回退即得分 |
| 异常可判定 | 25 | 异常码和可见结果稳定。技术变更写明「不适用」即得分 |
| 无实现泄漏 | 10 | 没有语言代码、目录和类图 |
