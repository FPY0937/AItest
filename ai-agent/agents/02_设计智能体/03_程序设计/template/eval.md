# 程序设计评估

## 评估对象

`ai-agent/spec/{需求项编号}/{子条目编号}/{子条目编号}_程序设计_{短标题}.md`

## 否决项（有一条即不通过）

- [ ] 详细设计未通过，或其中仍有阻塞程序设计的待确认
- [ ] 未指定目标代码库，或未指定写入目录（`git-repo-*` 或 `work/{需求项编号}/{目标库}/`）
- [ ] 一个子条目混入多个目标库的文件
- [ ] 技术变更写了业务类或方法契约，或未写版本落点、证明和回退
- [ ] 业务需求无方法级失败分支，或失败分支对不上详细设计的异常码
- [ ] 与工程规范或已检出仓的分层冲突，且未写成「待对照」或说明原因
- [ ] P0 行为没有对应的失败测试说明
- [ ] 应用规约已点名必须复用的公共方法被另写了一套
- [ ] 详细设计的字段、状态、异常码或处理顺序已变，本文件仍按旧契约写
- [ ] 详细设计写成既有资产，却没有标识、显式版本、文档位置、样例标记和相对样例还要写的差异
- [ ] 版本写成范围或 SNAPSHOT，或发布标识为空仍锁定
- [ ] 不兼容升级尚未读迁移章，锁定确认却写成通过
- [ ] 一次选用被写回应用规约的「必须复用」

## 评分（通过线 80）

| 项 | 分 | 标准 |
|---|---|---|
| 去向明确 | 20 | 目标库、写入目录、包路径都能指向 |
| 契约可编码 | 25 | 输入、成功、失败返回完整。技术变更改为：版本、证明、回退完整 |
| 同构 | 20 | 沿用既有分层或工程规范。未对照时明确写「待对照」 |
| 复用 | 15 | 公共方法是复用而不是重写。没有可复用方法时写明「无」 |
| 可验证 | 20 | 每条 P0 有对应的失败测试说明 |
