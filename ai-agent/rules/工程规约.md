# 工程规约

本文件对整个智能研发主库生效。各阶段智能体还须遵守本阶段 `rules/`。一句话需求从进入到测试完成，按 `ai-agent/skills/pipeline/sdd-flow-skill/skill.md` 选择下一阶段，不跳过本文件的门禁。

## 1. 单一事实源

- 长期知识只放 `docs/`。
- 进行中的需求规格只放 `ai-agent/spec/`。
- 已关闭需求规格迁入 `ai-agent/archive/YYMM/{需求项编号}/`。
- 需求跨多个代码库时，实现写在对应的 `git-repo-*` 检出里。这些目录是各代码库在本工作区中的工作副本，可以改代码。测试通过后，各自提交到各自远程。
- 目标库还没检出、或改动先放在规格库里时，实现写在 `work/{需求项编号}/{目标库}/`，分提时再提到目标库。
- 跨版本时，把要修改的那个版本克隆到 `git-repo-*`，代码写在这个检出上。
- 业务代码不写进 `ai-agent/` 或 `docs/`。主库 gitignore `git-repo-*`，不把节点仓的历史并进规格库。

## 2. 阶段门禁

| 要从…进入 | 前置必须存在且评估通过 |
|---|---|
| 概要设计 | 需求用例，且同一份文档中的需求确认为通过 |
| 详细设计 | 概要设计，且同一份文档中的架构师确认为通过 |
| 程序设计 | 详细设计 |
| 编码 | 程序设计已通过。其中有待锁定资产时，资产锁定已由人确认。写明「资产锁定不适用」的，随程序设计评估通过 |
| 测试设计 | 需求用例已确认通过。可与概要、详细、程序、编码并行 |
| 测试执行 | 编码 |
| 分提 | 测试执行完成：P0 有结果，失败项已关闭 |

未通过本阶段 `eval.md` 否决项，不得进入下一阶段。测试设计通过只表示用例可执行，不表示测试完成。P0 以需求用例里标成 P0 的验收为准。

已有用例上的缺陷不改范围、验收、优先级和影响服务时，从编码或测试打回，不重走概要设计。这些内容一旦变更，需求确认和概要设计的架构师确认都回到待确认。

详细设计改了字段、状态、异常码或处理顺序之后，对应程序设计作废，编码停止，直到程序设计重新通过评估。

编码只改程序设计点名的写入目录。本次新增或修改的有行为的类，要在该库的测试目录里有对应测试类；其对外方法要有成功和失败的测试方法。子条目的 P0 没有先失败后通过的记录时，不得进入测试执行。技术变更改为：程序设计点名的既有套件或构建没有实际结果时，不得进入测试执行。不为此新建业务测试类。

测试执行证明的是需求验收。编码记录里的单元测试通过，不算 P0 验收通过。

## 3. 编号

- 需求项：`1` 开头，如 `1000801`。
- 需求子条目：`5` 开头，如 `5000801`。
- 文件名：`{编号}_{类型}_{短标题}.md`，短标题不含空格。
- 编号未知时停止并向用户索取，禁止编造。

## 4. 智能体行为

- 先读规约和 `docs/`，再生成。
- 一句话诉求先进入需求智能体。只问会卡住当前阶段否决项的问题，一次一个。
- 范围外的改动必须先提问，禁止静默扩大。
- 不确定写成「待确认」，禁止用「等 / 相关 / 视情况」充当结论。
- 输出必须可被下一阶段直接消费。
- 程序设计必须写明每段代码的目标代码库。没有这一列，不得编码，也不得分提。

## 6. 资产查阅

查阅服务名是 `glue`。地址由人提供之前保持空白。令牌是环境变量 `GLUE_TOKEN`，不写入仓库，不放进请求正文。取程序包用现有仓库凭证，与 `GLUE_TOKEN` 分开。四个方法的入参、出参和允许阶段见 `ai-agent/mcp/glue.md`。业务代码不调用。代理不得签署需求确认或架构师确认。

能力地图上可单独验收的一行，在概要设计的资产步骤前写下 `intent`。未写不得查阅。检索单位是这一行，不是整份需求，也不是实现时会碰到的每个技术点。数据库写入若只是这个服务保存自己的数据，留在服务那一行里，不单独检索。澄清文档写成独立能力的，例如把事件发到 Kafka、对证件号加密、生成业务流水号，才另起一行。这一行的一句话和标签只取该段已经写明的词。

| intent | 查阅 |
|---|---|
| `add_capability` | 必须 `search_components`。包含进程内复用 |
| `new_service_or_call` | 必须 `search_components` |
| `replace_capability` | 必须 `search_components`，并确认迁移目标 |
| `upgrade_existing` | 不按能力检索。用代码库里已有标识，在程序设计 `get_component`。该版本标明不兼容时，再读迁移章，由人确认 |
| `in_range_change` | 不查阅。不得用来跳过一次本该查阅却失败的能力点 |

新服务里只有一部分用到某项能力时，服务本身一行 `new_service_or_call`，该项能力另起一行 `add_capability`。两行各自检索，互不取消。某一行零命中，只表示这一行沿原变更类型继续。

变更类型仍按技术变更、结构变更、范围内改动判定，命中即停。多个代码库本身不是结构变更。进程内资产不是新服务，也不是系统间调用。「新」对照 `docs/应用架构.md` 里已有的服务和调用，不看需求里有没有「新」字。只升级已有组件且对外行为不变，是技术变更，意图是 `upgrade_existing`。升级若改变返回、错误、时序或默认配置，变更类型改为结构变更，意图仍是 `upgrade_existing`。

| 命中 | 处理 |
|---|---|
| 恰好 1 条 | 只记下标识，标记「待详细设计绑定」 |
| 2 至 20 条 | 停住，一次只问一个问题。代理不得自行挑选 |
| 大于 20 条 | 只保留命中数和标签分布，先收窄再查 |
| 0 条 | 沿原变更类型继续，不编造资产 |
| 查阅不可用 | 停该能力点，标成未验证 |

`deprecated` 不算命中，除非本次需求写明保留该旧资产。`yanked` 不进检索。令牌缺失、地址空白、调用失败、协议版本对不上或索引未就绪，都是查阅不可用。`add_capability`、`new_service_or_call`、`replace_capability` 和需要读登记的 `upgrade_existing` 停住该能力点。真正无关的 `in_range_change` 可以继续。不得猜接口，不得改用仓库里的过期文档。

| 阶段 | 允许的查阅 |
|---|---|
| 需求 | 不查阅。不写组件标识，不写发布坐标 |
| 概要设计 | 仅三个必须检索的意图调用 `search_components` |
| 详细设计 | 用概要留下的标识点查；`get_component`；人指定一章后 `get_doc_section` |
| 程序设计 | `get_component`。升级且标明不兼容时，只读迁移章 |
| 编码 | 按锁定章节 `get_doc_section`；`get_sample`。人确认锁定之前不得取文件 |
| 测试设计、测试执行、分提 | 不查阅 |

一次选用只写在该子项的程序设计里，不回写应用规约的「必须复用」。把它升成以后每次必须复用，是另一次治理修改。

需求确认和架构师确认只打开下一设计阶段，不打开编码。有待锁定资产时，人确认锁定之前不得编码。确认通过不取消先失败后通过，也不取消审查。

准备在已有改动上继续编码，或准备把编码评估写成通过时，先由人做漂移分类。比较范围只包括该写入位置和依赖声明。代理不得代为分类。未分类时，继续编码的次数为 0。规格保持事实来源，不得按代码差异回写规格。

| 人确认的类别 | 去向 |
|---|---|
| 仅代码偏离 | 改代码，规格不变 |
| 方法、目标工程或资产版本变化 | 程序设计作废，编码停止 |
| 字段、状态、错误码或步骤顺序变化 | 先回详细设计，程序设计作废 |
| 范围、验收、优先级或受影响服务变化 | 需求确认和架构师确认都作废，已有测试通过作废 |
| 公共用法被破坏 | 按结构变更回到概要设计 |
| 无法判断 | 停止，只问一个问题 |
