# 分提 Skill

## 何时用

测试评估的执行结果为「完成」，且「可以分提」为是。

## 提交内容

按程序设计的去向，每个目标库单独提交：

- 代码已经在 `git-repo-*` 里：在该检出上提交，推到这个库自己的远程。
- 代码在 `work/{需求项编号}/{目标库}/`：把该目录中的文件放到目标库的原有路径后再提交。

以下内容留在规格库，不进入业务代码库：

- `ai-agent/`
- `docs/`
- 其他需求的 `work/`

## 步骤

1. 核对测试用例的执行记录：每个 P0 有结果，失败项已关闭。有阻塞则停止。
2. 按程序设计的「去向」表逐个目标库处理。一个目标库一次提交，不把多个库的文件打进同一次提交。
3. 在该代码库新建分支，分支名包含需求项编号。
4. 提交说明写明需求项编号、子条目编号，以及验证已完成。不使用强制推送，不跳过该库已有的检查。
5. 目标库的检查失败时，回到原来的写入目录修改，重新走编码审查和失败用例。
6. 每个目标库都提交成功后，在该需求的 spec 目录记下目标库、分支和提交标识。来自 `work/{需求项编号}/` 的副本在分提成功后删除。`git-repo-*` 保留为该库的检出。
7. 需求关闭时，把 `ai-agent/spec/{需求项编号}/` 迁入 `ai-agent/archive/YYMM/{需求项编号}/`。

## 禁止

- 不调用 glue。提交的依赖声明必须仍是程序设计锁定的那个显式版本。
- 不在 P0 仍失败或仍阻塞时分提。
- 不把规格库的智能体定义和长期知识拷进业务代码库。
- 不把未列入本次需求的其他 `git-repo-*` 改动一并提交。
